### **1. `HashMap::clone()` error**

```txt
method cannot be called due to unsatisfied trait bounds
Box<dyn Fn(&str) -> HttpResponse + Send + Sync> : Clone not satisfied
```

Why?
Because your `routes` field is:

```rust
HashMap<String, Box<dyn Fn(&str) -> HttpResponse + Send + Sync>>
```

And `Box<dyn Fn>` is **not `Clone`** by default.

🔧 **Fix:**
Instead of trying to `clone` the whole map for every connection, wrap it in an `Arc` (atomic reference counter) so all threads can **share** the same routing table:

```rust
use std::sync::Arc;

pub struct App {
    routes: Arc<HashMap<String, Box<dyn Fn(&str) -> HttpResponse + Send + Sync>>>,
}
```

Then in `App::new`:

```rust
pub fn new() -> Self {
    Self {
        routes: Arc::new(HashMap::new()),
    }
}
```

When inserting routes, use `Arc::get_mut` since we’re still building before serving:

```rust
pub fn get<F>(&mut self, path: &str, handler: F)
where
    F: Fn(&str) -> HttpResponse + Send + Sync + 'static,
{
    Arc::get_mut(&mut self.routes)
        .unwrap()
        .insert(format!("GET {}", path), Box::new(handler));
}
```

And when spawning threads:

```rust
let routes = self.routes.clone(); // now Arc is Clone
```

### **2. Missing `Read` import**

The error:

```txt
no method named `read` found for struct `TcpStream`
```

The `read` method comes from the `Read` trait. You only imported `Write`, but not `Read`.

🔧 **Fix:**

```rust
use std::io::{Read, Write};
```
