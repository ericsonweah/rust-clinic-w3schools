Perfect 🚀 — let’s make `HttpResponse` support **method chaining** so you can do things like:

```rust
res::ok("Hello")
    .with_status(201, "Created", "text/plain")
    .set_header("X-Powered-By", "RawExpress");
```

This mirrors Express patterns like `res.status(201).json(...)`.

---

## 🛠 Step 1 — Add builder-style methods to `HttpResponse`

```rust
impl HttpResponse {
    pub fn set_header(mut self, key: &str, value: &str) -> Self {
        self.headers.insert(key.to_string(), value.to_string());
        self
    }

    pub fn status(mut self, code: u16, text: &str) -> Self {
        self.status = format!("HTTP/1.1 {} {}", code, text);
        self
    }

    pub fn body(mut self, body: &str) -> Self {
        self.headers
            .insert("Content-Length".into(), body.len().to_string());
        self.body = body.to_string();
        self
    }
}
```

---

## 🛠 Step 2 — Adjust `res` helpers to return chainable `HttpResponse`

```rust
pub mod res {
    use super::HttpResponse;

    pub fn ok(body: &str) -> HttpResponse {
        HttpResponse::ok(body)
    }

    pub fn not_found(body: &str) -> HttpResponse {
        HttpResponse::with_status(404, body, "text/plain")
    }

    pub fn json(body: &str) -> HttpResponse {
        HttpResponse::with_status(200, body, "application/json")
    }
}
```

Nothing changes here — but now the returned `HttpResponse` can be chained.

## ✅ Example Usage

```rust
app.get("/", |_req| {
    res::ok("Welcome")
        .status(201, "Created")
        .set_header("X-Powered-By", "RawExpress")
        .body("Welcome to RawExpress with chaining!")
});
```

### Response

```http
HTTP/1.1 201 Created
Content-Type: text/plain
Content-Length: 35
X-Powered-By: RawExpress

Welcome to RawExpress with chaining!
```

## 🛠 Step 3 — Another example with JSON

```rust
app.get("/api", |_req| {
    res::json(r#"{"message":"ok"}"#)
        .status(200, "OK")
        .set_header("Cache-Control", "no-cache")
});
```

### Response

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 16
Cache-Control: no-cache

{"message":"ok"}
```

## 🚦 Why this works

* Methods consume `self` and return `Self` (builder pattern).
* Each call moves ownership and returns an updated response.
* At the end of the chain, the final `HttpResponse` is returned to the server.
